# BCHR++ enhanced v1 — optimization notes (2026-10-08)

## 1. Baseline audit

The source code is a minimal BCHR++ skeleton, not a complete causal hypergraph
architecture. `EvidenceEncoder` is learned-query pooling, `CausalDisentangler`
originally three independent linears, `CounterfactualContribution` an L2 score,
`CognitiveCompetition` a standalone softmax, `CausalHypergraphTransformer` a
standard Transformer, and `DualArbitration` two heads over the same pooled vector.
The source test invoked `BCHRPP(classes=3)` even though its constructor accepts
`output_dim`, so it was not a reliable test. `scripts/train.py` had the same issue.

The source MOSI checkpoint records validation MAE=0.950593, Corr=0.687500,
Acc-2=0.781659; **this was pre-existing**, not generated by the new methods.

## 3. Enhanced computation path

```
pre-extracted T/A/V + valid timestep masks
  -> modality projections -> LN / depthwise temporal mixing
  -> masked learned-query evidence compression
  -> gated task/context/nuisance factor projection + reconstruction
  -> unimodal prediction + confidence calibration (TRAIN)
  -> modality availability + confidence-softmax competition
  -> optional leave-one-out FAST prediction impact (detached bias)
  -> sparse top-K evidence graph + matched-slot incidence + Transformer
  -> conflict-aware FAST unimodal / SLOW relational arbitration
  -> regression / classification logits
```

Objectives are jointly trained as:

`L = L_main + a * detach(gradient_alignment) * L_unimodal + b * L_confidence + c * (L_recon + 0.1 L_orth)`.

The confidence target is `exp(-absolute_unimodal_error)` (detached) for regression.
The feature-gradient alignment coefficient is bounded in [0.5,1.5] rather than
letting a disagreeing auxiliary objective vanish. These are *chosen adaptations*
whose hyperparameters require a validation sweep.

## 4. Evaluation safeguards

1. Use official train/validation/test splits, identical pre-extracted features
   and common input shape when comparing the old and enhanced model.
2. The source MOSI checkpoint is strictly loadable through `legacy_model.py`.
   Enhanced checkpoints carry `version=bchrpp_enhanced_v1`.
3. No test set selection: best checkpoint is selected by validation MAE only.
4. Run at least three or five seeds with identical permutations before claiming
   superiority; report Std, confidence intervals and parameter/compute costs.
5. Modality masking and inverse-frequency sample weights are train-only. Both
   should be ablated; either may decrease clean-data performance.
6. For CH-SIMSv2, use predefined 2/3/5-class cutoff conventions; the 0-boundary
   belongs to the negative half under `(lower, upper]` binning as in source code.
7. Do not confuse a successful synthetic test or untrained random model metrics
   with published SOTA or reproducible performance.

## 5. Tests undertaken

* Masked time-step modification invariance and completely absent-modality tokens.
* Missing T/A/V handling, normalized source weights, all-missing rejection.
* Gradient propagation through all three input projections and reasoner.
* Regression and classification finite forward/backward.
* Historical checkpoint strict load, MOSI and SIMSv2 metric checks.
* Training, validation, checkpoint reload and test evaluation with tiny synthetic
  MOSI and CH-SIMSv2 fixtures (synthetic results intentionally NOT packaged).
* Enhanced checkpoint reloading through `scripts/eval_acc7.py`.

## 6. Suggested validation search (one variable at a time)

* hidden_dim: 64/128/256; query tokens: 2/4/8; graph top-K: 3/5/8.
* LR: 1e-4/3e-4; modality dropout 0/0.05/0.10; factor weight 0/0.01.
* Run baseline and matched full model separately on the same official features.
* Only retain changes that improve multi-seed validation and held-out test
  consistently; favor the simpler model when results are statistically tied.
